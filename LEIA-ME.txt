COMO PUBLICAR UMA ALTERAÇÃO
---------------------------
São dois passos, em dois lugares:

1. PUSH — mandar do computador para o GitHub
   Abra o VS Code na pasta "lp-ideal-conecta" (não na "lp").
   No terminal tem que aparecer (main) no fim da linha. Se não aparecer,
   é a pasta errada e nenhum comando de git vai funcionar.

      git add .
      git commit -m "o que mudou"
      git push

   ⚠ Sem o "git add ." o commit sai vazio. add é pôr na caixa, commit é
   fechar a caixa, push é enviar.

2. DEPLOY — mandar o EasyPanel buscar a versão nova
   Botão "Deploy" no topo da página do serviço lp-denis.

   ⚠ CHEGUE AO SERVIÇO PELA LISTA LATERAL do EasyPanel, nunca por link
   salvo. Em 22/10 o Deploy falhou duas vezes com a mensagem
   "Invariant failed", durando 0 segundos. A causa era uma URL salva
   apontando para /app/lpdenis (sem hífen). O serviço real é lp-denis,
   com hífen. A URL apontava para um serviço que não existe, e o erro
   não diz nada sobre isso.

   Três sintomas da mesma causa: tela do Source em branco, Deploy em
   0 segundos, e "Invariant failed".

⚠ Deploy sem push republica a versão antiga. A ordem importa.
⚠ Às vezes o PRIMEIRO Deploy republica a versão velha mesmo com o push
  feito. Se a página não mudou, clique Deploy de novo e espere.
⚠ Um Deploy publica AS DUAS LPs. Elas compartilham o serviço.

O autoDeploy está DESLIGADO. Se for ligado, o passo 2 deixa de ser
necessário — todo push republica sozinho.

⚠ NÃO CONFIRA O PUSH PELO raw.githubusercontent.com. Ele tem cache de
alguns minutos e dá falso negativo. Confira no próprio GitHub, na lista
de commits.

OS EVENTOS
----------
As duas páginas disparam os mesmos eventos, com os mesmos nomes e os
mesmos parâmetros. Isso é o que permite comparar.

Quatro botões de WhatsApp por página, todos com a classe .zap:

   nav          botão do topo (some no celular)
   hero         CTA principal da primeira dobra
   fechamento   CTA da última seção
   flutuante    bolinha verde do canto

O clique em qualquer um dispara DOIS eventos:

   Contact           (Meta)      → é a conversão da página
   clique_whatsapp   (Analytics) → comportamento na página

Os dois levam junto:
   origem / content_name  — o código do anúncio (o "bilhete")
   botao                  — em qual dos quatro botões a pessoa clicou

SÓ NA LP 02:
   ver_recurso  → dispara quando a pessoa toca numa das abas da seção
                  "A plataforma por dentro". Leva o nome do recurso.
                  Diz qual recurso as pessoas querem ver.

⚠ NÃO MARQUE ver_recurso COMO EVENTO PRINCIPAL no GA4. Ele é sinal de
interesse, não de conversão. Se virar conversão, o algoritmo otimiza
para quem toca em aba, não para quem chama no WhatsApp.

⚠ O Contact marca o CLIQUE, não a mensagem enviada. Do clique em diante a
medição depende da planilha manual. O pixel não atravessa para o WhatsApp.

⚠ COMBINADO DE 04/09: o dado por botão foi instalado para ficar guardado,
NÃO para ser lido nos primeiros 30 dias. Com volume baixo, diferença de
três cliques é ruído, não sinal.

Observação útil: o rótulo do botão funciona como medida de rolagem.
Quem clica no "hero" não leu a página; quem clica no "fechamento" leu
inteira.

O CÓDIGO DE ORIGEM — o "bilhete"
--------------------------------
No fim de cada index.html:

   const ORIGEM = (new URLSearchParams(location.search).get("o") || "LP01-DIRETO")

O padrão, decidido em 22/10:

   LP02-GADS-BLOQUEIO
    │     │      └─ ângulo do anúncio
    │     └──────── plataforma: META · GADS · LKDN
    └────────────── qual LP: LP01 · LP02

Sem parâmetro na URL: LP01-DIRETO ou LP02-DIRETO.

⚠ REGRA CENTRAL: A PÁGINA NUNCA AFIRMA DE ONDE A PESSOA VEIO. Quem
informa é a URL do anúncio. Até 22/10 a LP 02 dizia "Vim pelo Google"
fixo na mensagem e usava LP-GADS como padrão — as duas coisas mentiam
para quem viesse de outro canal. Foram corrigidas.

Regras do código:
   - Máximo 24 caracteres. Acima disso a página corta.
   - Só letra, número, hífen e underline. O resto é apagado por regex.
   - Vira maiúsculo sozinho.
   - Para testar, use -TESTE no fim. Casa com a conversão e é
     reconhecível depois.
   - NÃO ACEITA parâmetro dinâmico da Meta ({{ }}). As chaves são
     apagadas pela limpeza. O código é escrito à mão, um por anúncio.

O código entra sozinho na mensagem pré-preenchida do WhatsApp:

   "Vim pelo site [LP01-META-HISTORICO] e quero saber mais..."

UTM — só na Meta
----------------
   utm_source   = meta
   utm_medium   = cpc
   utm_campaign = {{campaign.name}}
   utm_content  = {{ad.name}}
   utm_term     = {{site_source_name}}   → devolve fb, ig, an ou msg

As chaves são parâmetros dinâmicos: a Meta preenche sozinha. Um link
serve todos os criativos de um ângulo.

⚠ Nome de campanha e de anúncio SEM ESPAÇO E SEM ACENTO. O nome entra cru
na URL. "Campanha Atendimento Perdido" vira Campanha%20Atendimento%20...

Exemplo completo de link de anúncio da Meta:

   https://lp.ideal.ia.br/?o=LP01-META-HISTORICO&utm_source=meta&utm_medium=cpc&utm_campaign={{campaign.name}}&utm_content={{ad.name}}&utm_term={{site_source_name}}

No Google, só:

   https://lp.ideal.ia.br/whatsapp-oficial/?o=LP02-GADS-BLOQUEIO

Testado em 23/10: o bilhete sobrevive às UTMs, ao gclid e a qualquer
ordem dos parâmetros.

A LP 02 chegou em 22/10 com as 8 imagens embutidas em base64, e o arquivo

A FAIXA CLARA — como foi feita (21/10)
--------------------------------------
A classe .sec--clara redefine os TOKENS DE COR dentro do escopo da seção.
Título, corpo, etiqueta, bordas, moldura das telas e o verde herdam
sozinhos. Não foi override elemento por elemento.

   background: #f4f7f7   (off-white, não branco puro)

⚠ APRENDIZADO QUE CUSTA CARO SE ESQUECER: ao colocar fundo claro, dois
elementos ficaram ilegíveis e nenhum painel avisou.

   etiqueta .meta        estava em 3,90:1  →  corrigida para 4,9:1 (#577074)
   tracinho verde        estava em 4,22:1  →  corrigida para 5,4:1 (#257158)

O mínimo da WCAG para texto pequeno é 4,5:1.

REGRA: cor que funciona sobre fundo escuro não funciona sobre fundo
claro. Trocar o fundo de uma seção obriga a recalcular o contraste de
tudo que está dentro dela.

OBSERVAÇÃO REGISTRADA (21/10): com duas faixas claras, a monotonia se
desloca para o terço final, onde ficam quatro seções escuras seguidas
(avaliações, implantação, FAQ, fechamento). A recomendação era deixar o
histórico claro também, formando um bloco de produto único. Decisão do
